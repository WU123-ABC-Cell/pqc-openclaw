# @openclaw/nostr

Nostr transport for the versioned OpenClaw PQC DM v1 protocol.

## Overview

The plugin sends authenticated hybrid post-quantum direct messages between compatible OpenClaw peers. It combines the NIP-44 conversation key with ML-KEM-768 inside an OpenClaw-specific `ocpqc1:` envelope and publishes regular Nostr events of kind `4444`.

This protocol is not NIP-04 and is not standard NIP-44. Ordinary Nostr clients such as Damus or Amethyst cannot decrypt these messages.

## Installation and setup

```bash
openclaw plugins install @openclaw/nostr
openclaw channels add --channel nostr --private-key "$NOSTR_PRIVATE_KEY"
```

The setup flow generates the local ML-KEM-768 keypair and publishes the public key as a signed NIP-78 addressable event. Discovery does not grant trust. Confirm the candidate SHA-256 fingerprint through an authenticated channel and explicitly pin it under that peer's lowercase Nostr public key:

```json5
{
  channels: {
    nostr: {
      privateKey: "${NOSTR_PRIVATE_KEY}",
      mlKemSecretKey: "${NOSTR_MLKEM_SECRET_KEY}",
      mlKemPeerPublicKeys: {
        "<peer-64-character-nostr-pubkey>": "<peer-base64url-ml-kem-768-public-key>",
      },
      relays: ["wss://relay.damus.io", "wss://nos.lol"],
    },
  },
}
```

Missing or invalid local keys prevent the account from becoming configured. Missing peer keys prevent outbound encryption. The plugin never silently downgrades a live relay message to NIP-04.

## Configuration

| Key                   | Type                   | Default                                     | Description                                             |
| --------------------- | ---------------------- | ------------------------------------------- | ------------------------------------------------------- |
| `privateKey`          | string                 | required                                    | Nostr private key (`nsec` or 64-character hex)          |
| `mlKemSecretKey`      | string                 | generated by setup                          | Base64url ML-KEM-768 secret key                         |
| `mlKemPeerPublicKeys` | record<string, string> | `{}`                                        | Pinned peer ML-KEM keys, indexed by lowercase Nostr key |
| `relays`              | string[]               | `['wss://relay.damus.io', 'wss://nos.lol']` | WebSocket relay URLs                                    |
| `dmPolicy`            | string                 | `pairing`                                   | `pairing`, `allowlist`, `open`, or `disabled`           |
| `allowFrom`           | string[]               | `[]`                                        | Allowed sender Nostr public keys                        |
| `enabled`             | boolean                | `true`                                      | Enable or disable the channel                           |

## Security properties

- A fresh 32-byte random nonce derives independent message keys for every envelope.
- The sender and recipient Nostr public keys, version, nonce, ML-KEM ciphertext, and message ciphertext are authenticated.
- The embedded ML-KEM ciphertext is decapsulated by the recipient and participates in key derivation.
- Event signatures and sender policy are checked before expensive decryption.
- Live relay subscriptions accept only kind `4444`; kind `4` is recognized only when draining records persisted locally before an upgrade.
- Signed ML-KEM announcements are discoverable from relays, but first-use fingerprints must be confirmed out of band and pinned explicitly.
- Rotations require explicit confirmation and a signed `previousFingerprint` link to the current pin; relay data can never silently replace a pin.
